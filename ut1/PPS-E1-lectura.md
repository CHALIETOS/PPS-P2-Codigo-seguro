# PPS-E1 · Lectura entrada→sink

|---|---|---|---|---|
| `validar.py` (interpretado) | `sys.argv[1]` en `main` pasado como argumento a `buscar_usuario(nombre)`. | 1. `con.execute(consulta)` (SQLi).<br>2. `os.system("logger acceso de " + nombre)` (Command Injection).<br>3. `eval(regla)` (Code Injection / RCE). | `validar_nombre`: `0 < len(nombre) <= 32`. **NO basta**: solo comprueba la longitud en caracteres; no filtra comillas, operadores lógicos ni metacaracteres de shell o Python. | En un modelo **interpretado**, las cadenas se pueden ejecutar como código (`eval`) o pasar al shell (`os.system`) dinámicamente. Con entradas como `"' OR '1'='1"`, la inyección SQL pasa, la inyección a logger se ejecuta, y revienta en la línea 30 con `SyntaxError` al intentar evaluar `len('' OR '1'='1') > 0`. |
| `Validar.java` (bytecode / JVM) | `args[0]` en `main` pasado a `buscarUsuario(nombre)`. | 1. `st.executeQuery(consulta)` (SQL Injection por concatenación).<br>2. Fuga de secretos: `String apiKey = "LAB-DEMO-NO-REAL-1234";` (clave en texto claro). | `validarNombre`: `nombre != null && nombre.length() > 0 && nombre.length() <= 32`. **NO basta**: solo valida no nulo y longitud máxima; permite cualquier carácter SQL malicioso. | En **bytecode (JVM)**, el fichero `.class` no oculta los literales ni la lógica: un decompilador (Jadx, CFR, Procyon) extrae la `apiKey` directamente del Constant Pool. Además, la concatenación directa en `Statement` traslada la vulnerabilidad al motor SQL en tiempo de ejecución. |
| `validar.c` (nativo) | `argv[1]` en `main` pasado a `buscar_usuario(nombre)`. | `strcpy(buffer, nombre)` hacia `char buffer[32]` (Stack Buffer Overflow). | **Ninguna**. **NO basta**: no comprueba ni puntero nulo ni longitud de la cadena de entrada frente a los 32 bytes reservados. | En **código nativo compilado**, C no verifica límites de memoria (bounds checking). Al copiar más de 31 caracteres (+ byte nulo), se desborda `buffer` en la pila, sobrescribiendo variables locales, el frame pointer y la dirección de retorno (`RIP`), provocando caída (`Segmentation fault`) o secuestro del flujo de ejecución (RCE). |

## ¿Cómo lo corregirías? (una línea por fichero)

- `validar.py`: Usar consulta parametrizada `con.execute("SELECT * FROM usuarios WHERE nombre = ?", (nombre,))`, ejecutar `subprocess.run(["logger", "acceso de", nombre])` sin shell, eliminar `eval()`, y validar con regex `^[a-zA-Z0-9_]{1,32}$`.
- `Validar.java`: Usar `PreparedStatement` con `?` para la consulta SQL y extraer `apiKey` a variable de entorno segura mediante `System.getenv("API_KEY")`.
- `validar.c`: Validar la longitud previa con `strlen(nombre) < sizeof(buffer)` o sustituir `strcpy` por `snprintf(buffer, sizeof(buffer), "%s", nombre)` garantizando el byte nulo final.
